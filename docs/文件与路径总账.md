# 文件与路径总账

> 目的：**不用再反复查证同一批地址**。凡是「重要的文件、目录、端口、外部服务」都记在这。
> 规则（新增条目照这个格式写，别自创）：
>
> **一、统一用相对项目根的路径**，一律 `/` 分隔（写成 `src/modules/tts.js`，不写 `E:\...`）。只有**项目外**的东西才写绝对路径，并注明在哪台机器上。
>
> **二、每条必须有四列**：
> | 列 | 写什么 |
> |---|---|
> | 用途 | 一句话说清它是干什么的，不写"配置文件"这种废话 |
> | 路径 | 相对项目根；目录结尾带 `/` |
> | 谁在用 | 具体到文件或程序名，方便改动前查影响面 |
> | 备注 | 只写**踩过的坑**和**不能想当然的点**；没有就留空 |
>
> **三、改动了内容就顺手更新这一行**（同一行改，不要追加新行）。
>
> **四、不确定的写「待确认」，不要写猜测**。写进来的必须是实测过的。

**启动脚本的硬规矩（2026-09-27 实测，别再踩）**

- `scripts/*.cmd` **一律纯 ASCII**。cmd.exe 按系统 ANSI 读 `.cmd`，中文注释在**普通行**里没事，但出现在 `( ... )` **括号块**里会把块解析拆坏 —— 块内那行剩下的英文被当成命令执行（实测复现出 `'see' 不是内部或外部命令`），后面的行跟着全乱，脚本走不到最后一步。
- 线上就这么废过一次：`cosyvoice-server.cmd` 的 `if not exist "%PY%" (` 块里有一行 `echo docs\... 总账.md section 9 ...`（中文路径），结果**语音合成服务起不来**（那个窗口停在 `pause` 等人按键），群里语音整条退回文字。改纯 ASCII 后立刻正常。
- 中文路径只能出现在 `.js` / `.py` / `.md` 里；`.cmd` 要提它就写英文（"the ledger in docs"）。写完自查：`scripts/` 下任何 `.cmd` 的非 ASCII 字节数应为 0。
- 另外：合成 / 变声 / 识别的窗口**关掉就等于关服务**（`start-all.cmd` 加 `--no-tts` 可跳过合成与变声）；服务不在时语音回复会**整条退回文字**，这是设计如此，不是 bug。

## 7. 音色页 + 四档输出（已建成，2026-09-24）

**① 音色注册表（读 + 试听）** —— 音色是**共享资源**，不属于任何单个机器人。
- 数据来源：`src/modules/tts.js` 的 `listVoices()`，认 vits / zipvoice 两种结构。**没有音色表** —— 音色就是 `.tools/tts/<名字>/` 目录本身，放进目录即生效。
- 接口：`GET /api/voices`（列音色 + 质量档 + 模板 + 转录目录 + 传 `?botId=` 时带本小时条数）+ `POST /api/voices/:id/say`（试听，回 wav 字节）。
- 界面：「音色」页，每个音色一张卡（名字/类型/大小 + 试听输入框 + 播放器），已实点验证过（点下去能出声）。

**② 「放音频自动生成音色」入口**（`src/modules/voice-forge.js`）
- 前端是**路径 + 文件名**，不做上传（浏览器拿不到本机文件）。另一种来源是「从已有音色复制」。
- 四步：ffmpeg 切 16k 单声道 wav → 参考文字取**带时间戳的人工转录**（`style-samples/transcript/<同名>.tsv`，**不要用识别结果**，会吐字发糊）→ 复制模板模型文件 → 写 `ref.txt` / `README.txt`。
- **窗口按整行对齐**：用户只报个大概起点（"p10 从 280 秒开始"），`alignWindow()` 把起点落到那一行的行首、终点取最后一行的行尾 +0.1 秒。这样音频和文字永远一一对应 —— 差半个字就会糊。实测：p10 的 280.382 秒起 12.206 秒，对齐成 280.382 起 12.306 秒，拼出的文字与 `zhangxiaoxiang/ref.txt` **逐字相同**。
- 模型文件用**硬链接**（`fs.linkSync`，跨盘退回复制）：造一个音色 0.2 秒、不额外占那 176MB。
- 造坏了/重名/中文名/参考段超长都会在**建目录之前**拦下；中途失败会把目录删干净，不留半个音色。
- 参考素材现成：`zhangxiaoxiang/` 是范本，官方两个 zipvoice 包在 `.tools/tts/` 下。

**③ 四档输出接线**（`src/modules/voice-out.js` + `pipeline.sendReply`）
- 设置项 `speak.voice = { mode: 'text'|'voice'|'prob'|'ai', prob, voiceId, sid, quality, speed, maxChars: 26, maxMessages: 2, maxMessagesForced: 4, perHour: 20, pauseMs: 0 }`。
- **语速（`speed`）**：0 = 用档位默认（克隆音色 `QUALITY.normal` 里写死 0.82 ← 用户当初拍板的「b 语速」）。给了值就覆盖档位里的 `--speed`，**vits 也支持**（帮助里写「Used by Supertonic, VITS, etc.」，实测生效）。用户嫌快就调小 —— 2026-09-24 晚他就是这么说的，小向先设成 0.72（慢约 12%），并发了 0.82/0.72/0.65/0.58 四档样本让他挑（同一条句子时长 6.4→8.2→9.5→12.2 秒）。网页「发言与频控 → 语音回复 → 语速」可改。
- `text` 走现在的路；`voice` 全语音；`prob` 按概率抽；`ai` = tail 里告诉它「想用语音就在第一行写 `[语音]`」，本地剥记号再合成（**不额外调模型**）。
- **讲题一律走文字**（`speaking.pickSentenceLimit().detailed`）：语音念一遍记不住、也不能回头翻。
- **超长一律退回文字**：`maxChars` 切条，超过条数上限就整条用文字 —— 切十条语音比发一段文字难听得多。**但模型自己点名要语音时（`ai` 档写了记号）额度放宽到 `maxMessagesForced`（默认 4）**：群里说「朗读一下这首诗」是明确要求，被 2 条卡掉会显得答非所问（2026-09-24 实测两次：猪咪把将进酒当文字发了，群里追一句「我的意思是让你朗读出来」）。
- **切分顺序：句末标点 → 读点（逗号顿号）→ 最后才硬数字**（`tts.splitForSpeech`）。以前是「每 `maxChars` 个字硬切一刀」，会把一句话从**词中间**劈开 — 群里出现过「…写得高大上，翻开全是」+「行列式。」「…我们先放一」+「放。」，听起来就是「话说一半断了」。宁可贵一点（一条长几个字）也不能切在词中间。
- **一条回复要么整条语音、要么整条文字**：发之前先 `canAfford()` 看配额够不够，再把所有分句**全部合成好**才发第一条；中途失败或配额被占走就整条退回文字。曾经的写法是「发一条试下一条」，那会出现「前半语音后半文字」的混合回复。
- 发送：`client.sendTo(kind, peerId, [{type:'record', data:{file:'file:///…'}}])`（file:// + 正斜杠）；记账走 `send()` 同一条路，所以全局频控、历史、复读记账都不漏。
- **记号只给日志看，不进历史**（`pipeline.send`）：日志里写 `[语音] …` 方便人回看，入库是纯文本。曾经两处都带前缀，结果模型从自己的历史里学会了这个记号，把 `[语音]` 写进正文中间发到群里（2026-09-24 实测一次）。
- **记号出现在哪都剥掉**，而且**四种括号都认**（`[ ]`、`【 】`、`〔 〕`、`（ ）`/`( )`）。两次真实泄漏：一次是写在句子中间、一次是模型照抄提示词里 `〔能力〕〔情形〕` 那种写法写了 `〔语音〕`（它想用语音念诗，结果记号没剥、还当文字发进群）。`「」` 故意不认 —— 中文正文里可能真的在引用「语音」这个词。
- **模型的发音上限在模型本身，不在参数**：`vits-zh-hf-theresa`（猪咪）偶尔念错多音字/声调（实测「矩阵的乘法」→「惩法」、「回头」在整句里 →「投」），换 `--vits-dict-dir` 两种指法都差不多（只有个别词变好）。ZipVoice 克隆（小向）在同一批句子上也有回读误差。
- **别拿识别回读当发音裁判**：短句 + 生僻词（尤其古诗）连**真人录音**都读不准，三个音色在同一批句子上"全错"更像是识别的锅。要判断发音好坏，最终还得人耳听；自动化的只适合发现「糊成一团」这种级别的故障。
- **不能拿合成语音当参考段去克隆**（实测失败）：用 theresa 念的 10 秒当参考造出来的 ZipVoice 音色，输出是糊的（回读「喂二那怎么行」）。原因还是那条规律 —— 参考录音与参考文字对不上（模型本身念不准），克隆就会吐字发糊。要用克隆就得有**真人/干净来源**的参考音频。
- 质量档 `auto` = 讲题用高质量（约 34 秒/条），其余用默认档（约 11 秒/条）。
- 合成出来的 wav 在 `data/tmp/tts/`，**发送那一刻不能删**；只在启动时清 3 天前的（`tts.pruneOutputs`）。

**④ 停顿（`pauseMs`，2026-09-24 晚加）**
- 起因：猪咪（vits 音色）「语速可以，停顿太短」。实测**`--tts-silence-scale` 对 vits 几乎没用**（0.2→6 之间只差 ±0.16 秒，还是噪声）——vits 的停顿烧在模型的时长预测里；那个参数只管分句处插入，而 zipvoice 的 1.7 是管用的。
- 做法：`pauseMs > 0` 时用 `splitClauses()` 按标点切句（**超上限只合并、绝不丢字**）→ 逐句各起一次合成程序 → `wav.joinWavs(parts, { gapMs })` 拼起来（纯 JS 写 16bit 单声道 wav，运行期不调 ffmpeg）。
- 代价：每个分句多起一次程序，vits 一句约 1.2 秒。实测 13 字三小句：不补 2.3~3.4 秒音频/约 2.2 秒算力；补 500ms → 3.3 秒音频/约 3.8 秒算力。**克隆音色一句 11 秒，所以 `pauseMs` 只建议给 vits 音色开。**
- 注意 vits 的时长预测带随机性：同一句话两次合成能差 1 秒（实测 2.30 vs 3.36 秒），对比时别拿单次结果当准。
- 界面：「发言与频控 → 语音回复 → 停顿(毫秒)」（每个机器人一套）+「音色」页试听框旁边也能临时填一个值试听。
- 当前值：**猪咪 = 250 毫秒**（用户听完 0/250/500/800 四档样本后选的 250；13 字三小句那句从 2.3 秒变成约 3.8 秒）；小向 0（zipvoice 自带 `--tts-silence-scale=1.7`，不需要补）。

**⑤ 克隆音色的两个「糊」的来源（2026-09-24 晚查清）**

小向（`zhangxiaoxiang`）一直发音模糊，查出来是两件独立的事：

1. **参考文字写错了字**。`ref.txt` 是从 **`style-samples/transcript/*.tsv`（机器识别版，带时间戳）** 里截的，里面把录音里的「**双曲线**」写成了「**专曲线**」（还漏了个「和」）。录音回读是「…分别是椭圆**双曲线和**抛物线」。
   - **教训：`.tsv` 不是人工转录，是机器输出**（`pNN.txt` 同源，`pNN.fixed.txt` 才是人工校订版，但没有时间戳，没法按窗口截）。之前文档里写的「人工转录」是错的。
   - 已改对（旧版挪到 `data/tmp/zhangxiaoxiang-ref-old.txt`，音色目录里只留该有的东西 —— 那个目录是要能整体拷给别人的）。
   - 造音色时**只能靠人核对**：`voice-forge.verifyRefText()` 用识别回读做粗筛，只挡「完全对不上」（阈值 0.6）。实测那句错 3 个字时相似度仍有 **0.833**，一个字错就足以让克隆发糊，整串相似度**查不出来**。
   - 界面据此给了两道提醒：「音色」页新增音色卡的说明里写明机器转录只当草稿；造完之后如果相似度在 0.6~0.9 之间，卡片下面会出现一行**橙色提示**，把识别回读的原话摆出来让人比着改。起始秒默认值给的也是小向那个能直接用的窗口（280.382）——填 0 会截到 p10 开头两句、不到 1 秒，被守卫挡下。
2. **开头 0.5~1.5 秒不稳定音频**（ZipVoice 这类参考音频提示模型的通病）。实测 26 字的消息里它占三分之一，听感就是「糊」。
   - 试过但**没用**：给参考音频加前后静音（0.3/0.6 秒都试了）、`--zipvoice-guidance-scale` 1/2/3、`--num-steps` 16、换**全精度**模型（39.8 秒/条，比 int8 慢 3.3 倍，回读没有可测差别）。
   - 有效做法：**事后掐**。`tts.findSpeechStart()` 把「想要的文字」和识别回读做整体对齐（允许识别错字 —— 实测它会把「同学们好」听成「同下」/「同意」，逐字匹配根本找不到起点），定位正题从第几秒开始；`tts.trimOnset()` 据此切掉开头。
   - **参考段改用 24 kHz**（`voice-forge.REF_RATE`）：ZipVoice 的声码器就是 24 kHz，以前把它压到 16 k 再喂进去更糊（用户听出来的）。造音色的 `-ar` 参数跟着模型走，默认 24000。
   - **多切一点 + 自检**：`trimExtraMs`（默认 250 毫秒，在定位到的起点之后再多切）、`trimFallbackMs`（默认 900 毫秒，定位不到时保守硬切）。切狠了会把第一个词咬掉（实测多切 450/650 毫秒时「同学们」整段没了、「作业记得写完」只剩「别熬太晚」），所以**掐完再回读一次自检**：内容覆盖掉超过 15 个点就自动还原（阈值必须相对自己比 —— 有的句子识别本来就只读出一半字，用固定门槛会把它们永远挡在门外）。两次都读不出来时按「不还原」处理。
   - **阈值别卡太死**：线上出问题的是**口语短句**（「在呢，又想我干嘛」7 个字），识别把它读成「艾O阿森纳里 S 在那遇想我干嘛」，对齐分 4/7≈0.43 —— 原来的门槛 0.5 直接放弃、只走兜底 0.4 秒，所以群里那些消息开头一直有怪声。现在 `minScore` 0.35、`minMatch` 3，短句也能定位。
   - **识别返回空不等于没救**：识别服务偶发返回空文本（同一个文件另一次回读又是好的），以前这种情况直接不掐。现在照样走保守切，让自检兜着。
   - 实测（今天日志里 8 条真实句子做基准）：旧参数 定位掐 4 / 兜底 2 / 没动 1 / 还原 1；**新参数 定位掐 5 / 兜底 3 / 没动 0 / 还原 0** —— 每条都切到了。
   - **仍然做不到的部分**：识别在伪影那一段会「读到」不存在的字，定位偶尔偏；而且**同一个句子两次合成质量能差很多**（实测一次掐完干净、另一次整段是废音）。掐不干净的句子就让它留着 —— 这是这套本地识别 + 这个克隆引擎的天花板。
   - 代价：每条多两次识别回读（约 1~2 秒）；识别服务不在就原样发。

**验证要求**：改完前端**必须真的打开页面点一遍**（试听按钮、档位下拉、生成音色、停顿框），光跑冒烟测试不算 —— 冒烟测试不执行 `app.js`。

## 7b. 变声（RVC，2026-09-25 加）

**为什么加**：CosyVoice2 的克隆已经够清楚，但「像不像某个人」这件事靠几秒参考音频做不到（参考段一糊整句就糊）。变声是另一条路：**先把字念标准，再换音色**，像不像由训练好的模型决定。

- **链路**：文字 → `cosy:biaozhun`（CosyVoice-300M-SFT 的「中文女」，播音级标准发音）念出来 → RVC 换成目标音色 → 发出去。变声只换音色、**不换读音**，所以声源必须是发音标准的音色（`voice.json` 里的 `sourceVoice` 指谁）。
- **id 前缀决定引擎**（`src/modules/voices.js` 的 `engineOf`）：`rvc:` → 变声，`cosy:` → CosyVoice2，其余 → sherpa。切换引擎 = 换个音色 id，没有额外的引擎开关。
- **降级**：变声服务没起来（或转换失败）时，**直接用声源那段音频**发出去，并在日志里带 `convertError` —— 宁可音色不对，也不能让这条回复没声音。
- **掐开头怪音只在 zipvoice 上做**（`voice-out.speak`）：CosyVoice2 和它的变声产物实测都没有开头伪影，而自检要额外调两次识别，不便宜。
- **参数**（音色目录里的 `voice.json`，界面「音色」页每张变声卡可直接改）：
  - `pitch` 音高（半音，-24~24）：女声换女声一般 0；听着闷往上加 2~4。
  - `indexRate` 索引比例（0~1）：越像、也越容易糊，默认 0.5。
  - `protect` 清辅音保护（0~0.5）：防止气声/齿音被啃掉，默认 0.33。
  - `sourceVoice` 声源：只能是 CosyVoice 音色（界面上从候选里选）。
- **注册一个变声音色**＝在 `.tools/rvc-voices/<名字>/` 下放 `model.pth`（+ 可选 `model.index`）+ `voice.json`。放好刷新页面就出现，能选、能试听、能调参。界面上的「新增音色」里选「变声 RVC」只会给出这段说明（它要现成模型，不是登记音频）。
- **现状**：`rvc:tomori` = 高松灯（+2 都是拼音），模型来自 `TogetsuDo/tomori-rvc`（HF 镜像）。**训练素材是唱歌**，说话声属于跨域，效果以人耳试听为准。

**顺带修掉的时长 bug**：CosyVoice 输出的 wav 是 **32 位浮点**（4 字节/样本），而算时长的代码一律按 16 位（2 字节）算 → CosyVoice 的「秒数」被算成**两倍**（3.92 秒读成 7.84 秒）。现在统一走 `wav.durationSec(info, 字节数)`，按位深和声道算（`cosyvoice.js` / `rvc.js` / `tts.js` / `voice-out.js` 四处）。

## 7c. 接话（2026-09-27 加）

**要解决的问题**：群里出现某些固定说法时，机器人要**主动**接一句，不用等别人 @ —— 而且这些「说法」和「怎么接」要能随时改。

- **和复读的区别**（`repeatEcho.js`）：复读是「好几个人说了同一句 → 模型自己决定要不要跟着说」，是涌现行为；接话是**你写死的规则**，命中就一定接。
- **规则存在库里**（表 `pickup_rules`，每个机器人一套）：`pattern`（触发词）/ `match`（contains 包含 | exact 完全相同）/ `reply`（要回的话）/ `mode`（fixed 回固定话术 | ai 让模型顺着接）/ `enabled` / `cooldown_sec` / `hits` / `last_hit_at`。界面在**「接话」页**：可单条加、**一行一个批量粘**、就地改、单条开关、删、清空；`hits` 与 `last_hit_at` 直接显示出来 —— 那就是「它真的在接」的证据。
- **两种回法的差别很实在**：`fixed` 是**本地直接发**，不调模型（不花钱），**API 掉线/未接入时照样能接**（和兜底话术同一类路径）；`ai` 需要模型在场，提示词里会写明「有人说了 X，这是你被设定好的接话点，顺着接一句，别解释自己在接话、别提关键词」。
- **同一个触发词可以配好几种回法**（2026-09-27 加）：回法框里**一行一种**（也认 `|` 分隔），命中时随机挑一句，且**同一段对话里挑过的先不挑**，全挑过一轮才允许重复（宁可重复，也不能因为「都说完了」彻底不接）。记录按 `${botId}:${sessionId}:${ruleId}` 存在内存里（同一群 = 一段对话；换个群重新开始），最多留 500 组防膨胀。
- **「自己接自己」的概率**（2026-09-27 加）：对方那句话里**已经含有你要回的内容**时（规则「原神 → 原神怎么你了」，对方正好说了「原神怎么你了」），照接会像复读机 → 只按 `settings.pickup.selfChance` 的概率接（默认 **0.3**，界面「接话」页可改，0 = 从不接、1 = 每次都接）。
  - **判定门槛 4 个字**：短回法不参与这个判定 —— 规则「吃了吗 → 吃了/没吃/你猜」里，对方说的「吃了吗」本身就含「吃了」，按子串判会把它当成「自己接自己」，正常命中反而被概率挡掉（实测踩过，写测试时才暴露）。
- **被找茬时回一个字**（2026-09-27 加，`settings.pickup.annoyed = {enabled, chance: 0.1, text: '急', when}`）：「对方没事找事」是**语义判断**，本地匹配做不到 → 交给模型：tail 里说明「什么情况算」+「想这么接就写一个 `[急]` 记号」，本地**按概率**决定发不发。这是项目里**语音记号**那套做法的复用（记号 + 本地裁决），所以规矩也一致：**记号在哪儿出现都剥掉、不管开关开没开**（语音记号泄漏过一次，教训）；旁边若还有一大段正文（>30 字）就当成顺手写的记号、照正文发；剥完什么都不剩且概率没中就不吭声。界面「接话」页有卡片可改概率/字/「什么算」的描述。
  - **判定要很严**（用户原话：「一定要很强烈的攻击才行，比如 nmsl sb nmd，而且这种情况下也要很少回」）：内置描述写明**只认直接辱骂**、普通的阴阳怪气/抬杠/玩笑都不算，并且提示词里叮嘱「拿不准就别用」；概率默认从 0.35 降到 **0.1**。
  - 代价：提示词每轮多一句话（在 tail 里，不影响前缀缓存）；不想要就关掉开关。
- **匹配**：触发词先过 `textmatch.normalize`（忽略大小写与全半角），`contains` 看子串、`exact` 要求整条相同；多命中时**取列表里靠前的那条**。
- **四道闸门**（照现有护栏来，没另发明）：① 接受名单 / 回复名单照旧管（被拦就不接）；② 会话被设成「关闭发言」时不接；③ 全局频控 `rate.allow`（每人/每群/每分钟那套）；④ **每条规则自己的冷却** + **每小时上限**（`settings.pickup.maxPerHour`，默认 20，防规则配太宽刷屏）。
- **优先级**：命令 > 接话 > 被 @（被动）> 复读 > 主动粗筛。**@ 了也接** —— 实测用户 @ 着说触发词时等的是那句固定回答，做成「被 @ 不抢」他直接反馈「回复不了」（2026-09-27）；只是被 @ 而没命中触发词的，还是走模型正常回答。私聊里 `kind` 不是 group，所以接话只在群里生效。
- 代码：`src/modules/pickup.js`（规则/匹配/冷却/限额）+ `pipeline.considerReply` 里的触发点与固定话术直发 + `buildTail` 的接话说明；接口 `GET/POST /api/bots/:id/pickup`（加/批量/改/删/清空一个 POST 全包）；设置项 `settings.pickup = {enabled, defaultCooldownSec: 60, maxPerHour: 20}`；「从另一个机器人复制配置」里也加了「接话」。
- **冒烟**：`scripts/smoke-pickup.mjs` 88 项（匹配、CRUD 校验、批量去重、冷却、每小时上限、命中记账、多回法/同段不重复/用完重来、自己接自己的判定与概率，以及管线层的：命中就接 / 固定话术不调模型 / 冷却内不接 / 被 @ 不抢 / ai 模式提示词 / 总开关 / 关闭发言 / 回复名单 / API 掉线仍接）。
  - 写这类测试要注意：**默认冷却 60 秒会把连续几条测试消息挡掉**（规则没单独填冷却时走默认值），测「多回法」这种连续场景要每次前 `pickup.resetCooldown()` + `rate.reset()`。
- 界面注意：批量结果写在一个**模块级变量**里再渲染（`pickupNote`），不能往卡片元素上写 —— `render()` 会把整张卡重建，写上去就看不见了（这个坑在音色页踩过，这次又差点踩）。

**接口（上游 rvc-api）**：`GET /api/v1/health`（`{status:'healthy', device, models_loaded}`）、`POST /api/v1/models/load {model_path}`（幂等，返回 model_id）、`POST /api/v1/convert/**file**`（path 版，body 里给 `input_path`，输出写在输入旁边 `<名字>_converted.wav`）。

**这次新增占的磁盘（约 11.2G）**：rvc 的 Python 环境 4.25G（含 CUDA torch）、公共模型 1.41G、高松灯模型 0.19G、**CosyVoice-300M-SFT 5.36G**。

- **必须用 `/api/v1/convert/file`**：不带 `/file` 的那个是 multipart 上传版，传 JSON 会 `422 Field required: audio`（踩过一次，当时静默降级成声源音频发出去，从日志才发现）。
- **探测要认应答形状**：本机别的程序也会回 200 —— 实测端口 6099 是 QQ 自己的本地服务，返回 `{"code":-1,"message":"Unauthorized"}`，只看状态码就会把别人的服务当成自己的。现在要求 `status==='healthy'` 或带 `models_loaded`。

- 输出是 **48 kHz 16 位**（输入 24 kHz 32 位浮点也会被它转好），时长按位深算才对。
- **测量教训**：这台机器的 `timeout /t N /nobreak` 在管道里**立刻返回**（实测 5 秒的等待只花 0.1 秒），所以「等 90 秒再看日志」其实一秒都没等 —— 我据此误判过一次「服务卡死」（GPU 0%、CPU 不动），其实它正在转。要等就用 `node -e "await new Promise(r=>setTimeout(r,毫秒))"`。
- **查过大半天的两件事，结论都是「没问题」**：① 怀疑过 faiss/OpenMP 在多线程里死锁（上游 API 用 `asyncio.to_thread` 跑转换），加了 `OMP_NUM_THREADS=1` 也照样跑 —— 去掉后同样正常；② 命令行 `rvc.exe` 与 API 结果一致（都出 48k wav、识别回读与原文相同）。**别再往这两个方向查**。
- **一个 NapCat 能同时接两个 WebSocket 客户端**：发小样的脚本直连 3011 用猪咪的号私聊发语音，全程没影响正在跑的机器人（日志里没有 disconnect）。

**踩过的坑**：

- `paths.json` **必须固定在项目根**：它是引导文件，放进可配置的目录就成了「配置在哪由配置决定」的循环。
- 界面上「恢复默认」是把输入框填成默认值、再由「保存」落盘；空串 = 删字段 = 默认，两处语义要保持一致。
- 保存前会**先试建目录**，建不出来就整个不写（免得存进一个让程序起不来的路径）；QQ 路径例外（不建目录，还没装 QQ 也能保存）。
- `.cmd` 一律 `for /f` 取路径，**不许再在批处理里手写目录名**；`napcat-start.cmd` 里那个 `E:\VibeCoding\...\.tools` 就是这么清掉的（换台机器/换盘就崩）。
- 冒烟里把默认值钉死成「改动前的老路径」——默认位置挪一下，等于全项目所有文件操作都在搬家。

## 一、运行环境与架构

| 项 | 决定 |
|---|---|
| 宿主 | 同一套代码跑 **Windows 电脑** + **安卓手机**（Termux 内），电脑为主开发目标 |
| QQ 协议 | **NapCat**（电脑版 / NapCat-Termux），需要小号，接受封号风险 |
| 模型 | `deepseek-flash`，端点用 **OpenAI 兼容**：`https://api.deepseek.com/v1/chat/completions` |
| 视觉 | 同一个模型原生支持图片（已实测：`input_modalities: ["text","image"]`） |
| 语音识别 | 本地 **SenseVoice-small**，电脑与手机用同一个模型，保证识别结果一致 |
| 界面 | 本地网页，**只绑 127.0.0.1**，无密码（同网段他人访问不到） |
| 存储 | SQLite + 文件 |
| 搬运 | **网盘手动**；PC 落地目录 `inbox\logs\`、`inbox\sync\` |
| 多机器人 | 每个机器人一份**独立配置**；支持「复制配置」与「风格卡引用」；每个机器人有「本机启用」开关 |

**多机器人的设备现实**：电脑能同时跑多个 NapCat 实例；手机上跑不动多个（每个 LinuxQQ 实例数百 MB + 识别模型 300–700MB），**手机实际只跑 1 个**，但界面能管理全部。

**自身机器人互斥**：程序登记所有自有的机器人 QQ 号，互相之间不响应、不复读、不计入"不同的人"。

## 三、行为规则

### 发言控制
- **主动 / 被动模式按群单独设**，私聊只做被动；主动模式下被 @ 仍必回
- 主动模式**两级闸门**：本地规则粗筛（被 @、提到名字、消息长度、距上次发言间隔、随机概率）→ 通过的才送模型判断要不要说
- 主动模式默认频控：每群每小时最多 5 条、两条间隔 ≥60 秒

### 频控（三档）
1. **重复内容**（更严）：同一用户，重复内容的最短间隔
2. **非重复内容**（较松）：同一用户，个性化回答的最高频率
3. **全局防风控**（不分人）：机器人整体发送频率上限

阈值均为**全局单一值**，按人分别计数。

### 复读
- 检测：群消息窗口内比对**内容相同但发送者不同**的消息
- 触发：不同发送者 ≥ **2** 人，间隔 ≤ **3** 条，窗口 **15** 条
- 本地先滤掉：太短、纯表情、纯标点、机器人自己发的
- 决策：候选 + 群上下文交模型判断"要不要跟"
- 执行：模型说跟 → **原样发出那句话**，只跟一次
- 生效范围：**仅主动模式**、仅群聊
- 计费归属：算入「重复内容」频控
- 相同判定：三档可切 —— **严格**（一字不差）/ **宽松**（去首尾空格 + 忽略大小写 + 忽略不可见字符 + 全角半角归一）/ **最宽松**（再忽略所有空格与标点）
- 该判定同时用于频控的「重复」判断

### 兜底回复
- **只在被 @ 或被叫名字时**触发
- **消息里带文字 → 交模型**（处理不了的部分换 `[视频]` 之类占位符）
- **只有纯视频/纯文件等 → 走兜底**，不调模型

### 图文混合
- 图片随文字一起理解；默认 `low` 档，长截图/认字场景自动切 `high`

### 其他
- 命令消息**不进对话记忆**
- 非管理员发命令**完全静默**
- 手机端语音条识别默认开，可关；关了之后该消息走兜底

## 四、命令

- 现有：`/learn goodex`、`/learn badex`、`/undo`、`/help`、`/voice on|off`（`/VoiceOn`、`/VoiceOff` 为别名）
- 命令解析**不区分大小写**
- 框架**可扩展**，命令下可带参数
- `/learn` 支持两种用法：**引用**机器人的某条回复（标记该条）/ **不引用**（标记机器人上一条）
- `/undo` **必须引用**定位：引用自己的命令消息，或引用机器人因该命令发出的消息，都认
  - 产物是程序更改（如 `/learn`）→ 回退更改，**不限时**
  - 产物是消息（如 `/help`）→ 撤回该消息，受腾讯 **2 分钟**限制
  - 成功**静默**（避免"已撤销"自身可被撤销的套娃），失败才告知
  - 引用非命令消息、或引用他人消息 → 静默忽略
- `/help` 内容 = **你编辑的正文** + **自动生成的命令列表**（每条说明也可编辑），采用**手册风**小样 A
- 命令历史**按会话分**（私聊/各群独立）

## 五、风格系统

- **一份人格**（甲方案）：对所有会话用同一份风格；按「人」分的只是记忆与印象
- 来源三合一，全部整合进**同一张风格卡**：
  1. 音频离线转写（主力，几小时素材）
  2. 文字样本（`style-samples\samples.txt`，已有 3 条）
  3. 手动编辑（`style-samples\notes.txt` + 界面）
- **风格卡是唯一进 prompt 的东西**（几百到一千多字 + 5–15 条精选例句）；几万字原文只作素材库存档
- 生成人格卡时**剥离真实姓名/学号**，只保留行为模式
- 加新音频 → **增量学习**：只转写新增部分，只更新受影响项，不推翻已调好的内容

### 学习
- 素材来源 **A + B**；**A 可随时开关**（关且 B 无标记时学习禁用并提示）
- 开关只控制「学不学」，不控制「记不记」
- B 的标记：**界面聊天记录页 👍/👎 为主**（含负面标记），`/learn` 命令为捷径
- 标记例子分两层：进学习素材池 / 可钉为风格卡固定例句
- 采纳方式默认**全部人工审核**（可选"低风险自动采纳"）
- 学习时明确要求找"新的、缺的"，避免自我强化导致风格越学越窄
- **快照**：基准快照（你命名，永久、不被覆盖、不被自动清理）/ 自动快照（每次学习前自动存，留最近 20）
- 快照随数据包同步

## 六、印象系统

| | 记忆 | 印象 |
|---|---|---|
| 是什么 | 对话历史原文 | 机器人对某人的长期认知 |
| 生命周期 | 滚动淘汰（默认 20 轮） | **长期保留**，不受淘汰影响 |
| 生成 | 直接记录 | 提炼（自动 + 手动） |

- 内容两块：**事实**（称呼、提过的事）+ **感觉**（熟络程度、互动习惯）
- 形成：周期性提炼（可关）；**手动改的优先级最高，不被自动覆盖**
- 使用：每次与该人对话时随请求送入
- **位置约束（关键）**：必须放在**会话历史之后、当前消息之前**，绝不进 system prompt——否则群里多人交替说话会让前缀每次都变，缓存全线失效
- 容量：每人默认上限 300 字，超了自动压缩
- 跨群共享：同一个人的印象在所有群与私聊通用

## 七、会话与上下文

- **私聊上下文按人**分
- **群聊上下文按整个群**分（多人交替说话是一条连贯的对话流）
- 「人」这一维（名单、权限、印象、绑定）**跨会话共享**
- 大小号绑定合并的是「人」这一维，**不拆开群上下文**
- 绑定规则：绑定前各自已有上下文 → 拼接合并；解绑 → 共同上下文两边各留一份副本；小号绑定前未发言 → 解绑后按新用户算

## 八、缓存与成本

### 缓存优化（我方承诺的设计）
1. system prompt **一字不变排最前**（人设 + 风格卡 + 规则 + 例句）→ 所有会话共享同一段公共前缀
2. 时间、昵称、群名、消息元数据、**人物印象** → **全部下沉到最后一条用户消息**
3. 历史**顺序追加**，不重排、不插队
4. 前缀里**不放任何随机元素**
5. 风格卡变动 → 一次全价请求，之后恢复

### 已实测数据
| 项 | 结果 |
|---|---|
| 缓存是否自动 | 是，无需额外参数 |
| 第二次相同前缀命中率 | 1280 / 1517 ≈ **84%** |
| 两个端点缓存是否互通 | **互通**（OpenAI 格式建的缓存，Anthropic 格式请求读到） |
| 图片 token（1920×1080 JPG） | `low` ≈ **220** / `high` ≈ **980** |
| 图片单价 | low ≈ 0.00024 元/张，high ≈ 0.001 元/张 |
| 思考 token | 服务端默认档 = **high**。`completion_tokens = 思考 + 可见输出`，**max_tokens 太小会被思考吃光、返回空字符串**（实测 max_tokens=32 时 32 个 token 全被思考占用） |
| 思考档位字段名 | **`reasoning_effort`**（实测确认）。写成 `effort` 会被静默忽略 |
| 各档位思考量 | low ≈ 77 / high ≈ 110 / max ≈ 132 / 不传 ≈ 109（同一道题的 token 数） |
| `low` 的效果 | 比默认档**省约 39% 输出 token**，且回答更直接（输出 79 vs 130） |

**成本结论**：图片不是开销大头，**输出文本的长度与条数才是**——所以频控阈值本质上是成本闸门。

### 思考档位（三态，界面可切）
| 任务 | 档位 |
|---|---|
| 生成聊天回复 | 低 |
| 复读要不要跟的判断 | 低 |
| 图片理解 | 低（长截图/认字自动切高） |
| 风格提炼 | 高 |
| 印象提炼 | 高 |
| 摘要压缩 | 高 |

### 同一 key 下多机器人的相互影响
- **并发**：按**账号**计，与 API Key 无关；`deepseek-flash` 上限 **2500**，实际远够。程序内仍做全局队列 + 指数退避（遵守 `Retry-After`）
- **缓存**：按「账号 + 相同前缀」匹配。**共用同一份风格卡的机器人共享缓存，几乎不额外花钱**；风格卡不同则各自独立、互不干扰。**不传 `user_id`**（传了会强行隔离 KVCache，反而更贵）
- **账单**：DeepSeek 侧账号级合并，分不开；**程序内按机器人/群/人分别统计**
- 并发不够可**免费申请扩容工单**

### 保温（默认关）
- 方法：每 N 分钟（默认 4）发一个只含公共前缀的极小请求（`max_tokens=1`），**绝不在 QQ 发消息**
- 只能保住公共前缀，保不住各会话历史
- 代价：6000 token 前缀约 0.00013 元/次，一天约 0.05 元
- 先跑几天收集真实 hit/miss 再决定开启（官方口径 TTL「几小时到几天」，第三方实测约 5 分钟，差距大）

## 九、安全

- 对外请求（下载 QQ 图片/语音）**仅允许 http/https**，发请求前**校验 host，拒绝 localhost、环回、私有与保留地址**

- 密钥不从源码、示例、测试中读取字面量

## 十、语音处理

### 离线（风格学习）—— 已跑通，实测数据如下
- 素材：Bilibili 合集 BV1Gr4y187aS（东南大学张小向《线性代数先修课》），21 个分P、4.27 小时、单人、无 BGM、口音不重
- 流程：yt-dlp 取音频 → ffmpeg 转 16kHz 单声道 → silero-VAD 切段 → SenseVoice-small int8 转写 → 术语校正 → 提炼进风格卡
- **B 站无加密**：DASH 分离流 + WBI 签名，yt-dlp 内置处理，**全程不需要登录**
- **无可用字幕**（yt-dlp 与 player/v2 接口均返回 0），必须走 ASR
- 实测：4.27 小时音频 → **转写 10 分钟**（RTF 0.037，约 **27× 实时**，**纯 CPU 即可，不需要 GPU**）
- 产出：**68,046 字**，落地 `style-samples\transcript\*.fixed.txt`（`.tsv` 带时间戳，可回听核对）
- **热词功能不可用**：sherpa-onnx 强制要求 `modified_beam_search`，SenseVoice 是 CTC 架构只支持 greedy，配热词直接报错。改用**转写后术语校正表**，已修 419 处（"矩阵"被听错 265 次，有矩证/举证/取证三种变体）
- **术语精度不影响风格提炼**：风格学的是"怎么说"（句式、推进语、称呼、语气词），术语是"说什么"。校正到此为止
- **标点学不到**：语音本身无标点，转写标点是模型补的，不是说话人习惯。风格卡里"标点习惯"只能从文字样本学
- 云 ASR **不采用**（本地够用、不花钱、不出电脑）

### 运行时（语音条识别）
- 电脑与手机都做，手机默认开（可关）
- 手机为 CPU 推理：模型 250–500MB、内存常驻 300–700MB、一条 10 秒语音约 1.5–5 秒
- 手机门槛：**≥4GB 运存 / ≥64GB 存储 / 骁龙 7 系或同级**（待确认机型）
- QQ 语音条为 SILK 格式，NapCat 自带转码，需系统装有 ffmpeg

### 运行时（声音生成 · 仅电脑端）
- **只在电脑端运行时可用**（手机跑不动语音合成），手机端该功能自动隐藏/置灰
- 控制：命令 `/voice on|off`（别名 `/VoiceOn`、`/VoiceOff`）+ 界面总开关 + 界面按会话开关
- 音色：**每个机器人一套独立音色**（与其他设置同样的独立逻辑）
- 引擎：先用**零样本克隆**验证（给几秒参考音频即出效果，无需等训练），不足再上少样本微调；候选 GPT-SoVITS / CosyVoice2，实测后定
- 素材：直接复用 `style-samples\audio\` 里的几小时录音
- 默认策略：文字照发，语音条**附加**发送；过长回复降级为纯文字（默认 30 秒 / 约 80 字）
- 风险：语音条需上传音频文件，**比文本更容易触发风控**；第三方协议发的语音条在 QQ 客户端偶有播放异常，需实测

> **实现后记（2026-09-24，实际做法与上面几处不同，以 `docs/文件与路径总账.md` 第七节为准）**
>
> 1. 引擎没用 GPT-SoVITS / CosyVoice2，用的是 sherpa-onnx 自带的 **ZipVoice 零样本克隆**（和本地识别同一套二进制，纯 CPU、不装 Python）。
> 2. 控制方式：`/voice on|off|auto|prob`（`/VoiceOn`、`/VoiceOff` 是别名）+ 网页「发言与频控 → 语音回复」的四档 + 网页「音色」页。**没做**「界面按会话开关」——档位是每个机器人一套（`speak.voice`），不按群分开。
> 3. 输出策略改成**四档替换**（只发文字 / 全用语音 / 按概率 / 由模型自己决定），不是「文字照发、语音附加」：附加会让每条消息都变成两条，而且语音比文字更容易触发风控。
> 4. 降级阈值按实测定：一条 26 字（合成约 11 秒）、一次最多 2 条，超了就整条走文字；讲题类回答一律走文字。原定的「30 秒 / 约 80 字」折算下来太长了。

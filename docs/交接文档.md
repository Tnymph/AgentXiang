# 交接文档

给接手维护这个项目的人（或 AI）。README 讲"这是什么、怎么用"，这里讲"怎么改、为什么这样、坑在哪"。
细节清单（每个目录/模型/端口的账）在 [文件与路径总账.md](文件与路径总账.md)，功能与默认值在 [需求确认书-v1.md](需求确认书-v1.md)。

## 当前状态（2026-10-13）

- 功能完整，**在真实 QQ 群里跑着**：两个机器人（客服小向、猪咪群友），各自一套 NapCat。
- **29 套冒烟测试、全绿**（`node scripts/test-all.mjs`，约 1200 项检查）。
- 语音三件事全通：识别（SenseVoice 常驻服务）、合成（sherpa / CosyVoice2）、变声（RVC，GPU 上每句 0.6~1.4 秒）。
- 模型都在本机 `.tools/`（约 20G，不随仓库走）；**路径可自定义**，见 README「路径可以自定义」。
- 已知缺口与"还没做"的清单在总账第 8 节。

## 技术形态（先记住这三条硬约束）

1. **零 npm 依赖**。只有 `package.json` 里的名字，没有任何 `dependencies`。可用的是 Node 22 内置模块：
   `node:sqlite`（数据库）、全局 `WebSocket`（收 QQ 消息）、`fetch`、`node:crypto`。**加新功能不要引入依赖**（打包手机版靠的就是这一点）。
2. **QQ 接入只有一条路：NapCat**（OneBot 11 over WebSocket）。官方机器人 API 读不了**合并转发**的聊天记录，而这是最常见的素材来源；Lagrange 已归档。一个 NapCat 实例只服务一个 QQ 号。
3. **本机 Web 界面是唯一控制台**（`src/web/public/`，无构建步骤，改完刷新即可）。只监听 127.0.0.1。

## 三分钟跑起来（Windows）

```bat
:: 1) Node >= 22.5
:: 2) 模型/工具放好（照 docs/文件与路径总账.md 第 9/10 节装；只想聊天可以不装）
:: 3) NapCat 登录 QQ 小号（scripts\napcat-start.cmd）
scripts\start-all.cmd --asr
:: 4) 打开 http://127.0.0.1:6188 →「接入与密钥」填 DeepSeek 密钥
node scripts/test-all.mjs          :: 确认环境无恙（没有模型/素材时部分套件会跳过或红，见 README）
```

手机（Termux）部署脚本在 `phone/`；手机上没有语音合成/变声（芯片太慢），语音档要关。

## 架构：一条消息的旅程

```
QQ 服务器 ⇄ NapCat(WS) → src/onebot.js     连收发、自动重连（8 秒建连看门狗）
                        → src/manager.js   每个机器人一个 BotWorker
                        → src/message.js   事件规范化（at 段只有 QQ、要补名字；媒体与文字分两条到）
                        → src/pipeline.js  主流程 = 选谁说话 → 组装提示词 → 调模型 → 分条发送
                            ├─ src/cmdline.js + modules/commands.js   命令（@机器人 /learn …）优先
                            ├─ modules/pickup.js    接话：命中触发词直接发固定话术（不花钱）
                            ├─ modules/repeatEcho.js 复读
                            ├─ modules/speaking.js  发言决策（主动/被动/频控/时段）
                            ├─ src/prompts.js + modules/persona.js  提示词（系统段冻结、动态放尾部）
                            ├─ src/llm.js       调 DeepSeek（含搜索工具回路）
                            └─ modules/fallback.js 兜底（视频/文件/语音条/AI 离线）
                        → modules/voice-out.js  语音四档：tts.js → cosyvoice.js → rvc.js
```

- **数据库**：`src/db.js`（WAL；新表用 `create if not exists`，**新字段必须写进 `MIGRATIONS`**，否则老库缺列不报错——测试库都是新建的，测不出来）。
- **配置**：全局在 `data/config.json`；每机器人一份存在库里（`botSettings(id)`，**不缓存**，改完立即生效）。
- **密钥**：`src/secrets.js`，AES 加密落 `data/secrets.json.enc`，界面只给掩码。**密钥存储是全局一份**（按 bot_id 分槽），测试用 **bot id ≥ 999000**，否则会把正在跑的机器人的密钥清掉。
- **路径**：全部来自 `src/paths.js`（唯一来源，四个根可自定义）。**任何地方不许再拼 `data/`、`.tools` 这类字符串**；`.cmd` 脚本用 `scripts/_dirs.cmd` + `print-dir.mjs` 拿路径。

## 改代码的规矩（每一条都有事故背景）

1. **改完先跑测试**：`node scripts/smoke-<那个模块>.mjs`，提交前 `node scripts/test-all.mjs`。
2. **前端改完必须真开浏览器点一遍**（`npm start` 后开 6188）——冒烟测试全是 API 层的，`app.js` 一行都不会被执行。
3. **代码改动要整个重启程序才生效**：界面上「机器人本体 → 重启」**不会重新加载模块**（它是进程重启，但页面上的"重启机器人"只重连 QQ）。改完代码用 `scripts\start-all.cmd` 重拉，或者杀掉 node 再起。
4. **`.cmd` / `.sh` 一律纯 ASCII**：cmd.exe 按系统 ANSI 读脚本，一个中文字符就能让它把整段解析错位（实测：注释里一个汉字，后面所有行都被当成命令执行）。中文只写在 Node 文件里。
5. **`.cmd` 里不写尖括号**：`<name>` 会被当成重定向，整行乱掉。
6. **模型输出要有"本地裁决"**：让模型在尾部说明里写个记号（如 `[语音]`、`[急]`），**本地代码永远剥掉记号再决定发什么**。别让模型直接决定系统行为。
7. **思考 token 与正文共享 `max_tokens`**：上限小了会出现"正文被截断/空回复"。学习（16384→32768 重试）和对话回复（撞上限翻倍）已防；印象（2048）目前够用但没防——见总账第 8 节。
8. **系统提示词保持冻结**（前缀缓存）：一切动态内容（时间、名单、素材）只加在 tail。
9. **测试数据用假号**：测试库用独立文件名（`test*.sqlite`），bot id ≥ 999000，QQ 号用 `10000001` 这类明显假号，群号用 `555001`。
10. **本机时间测量别用 `timeout`**：这台/这类环境里 `timeout /t N` 在管道下**立刻返回**，等 N 秒实际等了 0 秒（我据此误判过"服务卡死"）。要等就用 `node -e "await new Promise(r=>setTimeout(r,ms))"`。

## 排障速查

| 现象 | 先看哪里 |
|---|---|
| 机器人不回复 | `data/logs/chat-YYYY-MM-DD.log` 里的 `branch=` —— `skip:原因` 就是答案 |
| 服务起不来 | `data/logs/asr-server.log`、`.cmd` 窗口里的报错、总账第 5 节（端口表） |
| 学习/印象报"截断/没有输出" | 思考吃预算（规矩 7），看 `usage` 里的 reasoning 占比 |
| 语音发不出去/很小 | `data/tmp/tts/` 里有没有文件；NapCat 要能读到这个路径（发送前别删） |
| 变声不对 | RVC 服务（6012）与 CosyVoice（6011）**都**要在线；`voice.json` 的 pitch/indexRate |
| 界面按钮无效 | 先确认页面版本（强刷）；启停接口要 `X-AgentXiang` 头，跨域会被拒 |
| 改完路径没生效 | 需要**整个重启程序**；界面「位置」卡片里「待重启生效」标记就是提醒 |
| 数据库疑似缺列 | 老库要过 `MIGRATIONS`（规矩 1 的测试测不到这种） |

## 最贵的几个教训（别再踩）

- **`timeout` 不等人**（见规矩 10）；**`--input-type=module` 的多行 `node -e` 会被 cmd 吃掉**，临时脚本写成 `.mjs` 文件。
- **测试夹具必须按真实形状来**：NapCat 的 at 段**只有 qq 没有 name**，当年夹具里带着 name，于是"@ 显示成 QQ 号"这个 bug 一路绿灯上线。
- **默认值改一处、全项目动**：路径改造时冒烟里专门钉死"默认 = 改动前的老路径"。
- **存下来的设置会覆盖代码里的新默认值**：改默认值（如概率）后，已存在的机器人还是老值，要么界面改回要么脚本写回。
- **自动刷新会重建页面节点**：交互前先暂停（侧栏勾选框）；把结果写进被重建的元素 = 看不见。
- **别信"看起来差不多"**：时长按位深算（32 位浮点 wav 会把 2 秒算成 4 秒）、RVC 探测要认应答形状（QQ 自己的 6099 端口也回 200）。
- **删东西之前看清楚**：这台机器的规则是"但凡有一点用都不要删"——每次删都先查引用、先备份能恢复的来源（例：清 6.05G 时 SFT 模型 5.36G 是确认推理链路零引用才删的）。
